# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Godot 4.7 (GDScript only) prototype of `docs/PRD.md`: a pause-and-play tribe RTS where node-triggered LLM "Task Contracts" are negotiated once and then executed by a deterministic state machine. README.md documents gameplay systems in detail.

## Principles

**Configuration over hardcoding.** Rules are data; scripts are the machinery that runs them. Tuning numbers, chances, timings, texts, events, dilemmas (choices, costs, outcomes), reactions and their triggers belong in data files (`config/*.json`, culture packs, scenarios, `D.*` tables), not in `match` branches and literals inside the logic. Code provides a small set of named verbs (story actions, reaction responses, effect stats, conditions) and the data picks and parameterizes them. When adding or changing a feature, add keys or a reusable verb rather than a one-off branch; when touching code that still hardcodes these things, move them to data. Reuse the shared formats (one dilemma format, one action runner `story.run()`, one condition checker `story.holds()`) instead of writing another. Keep in code only what must stay trusted or is pure mechanics: the sanitizing of LLM output, pathing, rendering, and the executor itself.

**Ready for an LLM game master.** The goal is a fully LLM-driven experience in which an LLM acts as game master and controls the game through MCP endpoints (reading the world, firing events, posing dilemmas, spawning, changing weather, steering clans and people). Design every system so an external caller could drive it:
- Every way the game can change is a named operation that takes JSON-shaped arguments (`story.run()` actions, `sim.react.trigger(event, ctx)`, event/dilemma ids, contract plans), not something only reachable from a UI handler or buried in a tick. The HUD should call the same operations a game master would.
- Every state a game master needs is readable as a plain dictionary (`hz.summary()`, `evo.world_ctx()`, `rivals.summary()`, `folk.summary()`...). Keep these up to date when adding state.
- Input from outside is untrusted, like LLM contract output: whitelist ids, clamp numbers and map aliases at the boundary (`contracts.sanitize()` style), and never let it bypass the rules.
- The sim stays deterministic and LLM-free inside its tick; it reports outward through signals (`event_fired`, `log_added`, `alert_raised`, `feat_added`...) that a game master could subscribe to, and an offline fallback (`persona_engine.gd`, the built-in rules) must keep the game playable without one.

## Architecture

**No `class_name`, no autoloads.** Scripts reference each other via `const X = preload("res://scripts/x.gd")`. `entities.gd` holds the plain data classes as inner classes (`E.Unit`, `E.Predator`, `E.ResNode`, `E.Structure`, `E.Contract`).

**Layering (keep it):**
- `sim.gd` — the whole deterministic simulation, a `RefCounted` with no rendering and no LLM. Ticked at a fixed 0.05 s step from `main.gd`. Talks outward only through signals (`contract_interrupted`, `event_fired`, `contract_finished`, `log_added`, `alert_raised`) and by setting `sim.paused`. It owns sub-systems as plain objects: `contracts` (`contract_system.gd`), `evo` (`evolution.gd`: practice-based tech insight, knowledge keepers/oral loss, culture values → traditions, eras), `hz` (`hazards.gd`: seasons, weather, wolves/raids, sickness, famine). `rivals` (`rivals.gd`: rival clan villages owned `"rival:<id>"` — excluded from pop cap/fog/warmth via `sim.ours(s)` — relations, first-contact/demand events, raids, envoys → `envoy_arrived` signal → HUD parley via `llm.parley()` (rival chief node; offline `rivals.chief_reply()`; `sanitize_terms`/`check_reply` guard the reply) → `seal()` treaties; trade caravans (`kind "trader"`) and teachable clan techs; alliances/vassals (`at_peace()`), `legacy` (`legacy.gd`: victory paths, defeat, `llm.saga()`), and `inv` (`inventions.gd`: everyday inventions from `D.INVENTIONS` — practice passed on by `evo.practice()`, gated by needs; effects are queries like `inv.heal_mult()`, `inv.carry_bonus()`; plus `inv.feat(kind, text, who, {desc, source, history, at})` records the tribe's firsts for the Achievements panel and emits `sim.feat_added`, which the HUD celebrates with a paused dialog and a snapshot of `at` (a `SubViewport` sharing the world, with `world.clean` hiding labels) — call it from new milestone code), `folk` (`folk.gd`: children are units with `role "child"` that play instead of working and come of age after `CHILD_DAYS`; tribe `mood` scales `work_mul`; art jobs make `stock["goods"]`, hut `decor` and `treasures`; festival events via `folk.pending`; trade trips with `role "trader"`; `_new_sim()` sets `folk.festivals = false`), `nat` (`nature.gd`: lightning, wildfire, spring floods, the Fire Mountain volcano, eclipses (an event via `nat.pending`), earthquakes; queries like `nat.darkness()`, `grow_mult()`, `food_mult(s)`, `alarm()`; `sim.cause_hint` names a death cause around `hurt_unit`). Natural finds are `ResNode`s whose `kind` is a `D.FINDS` id; they are unknown (not gatherable) until `discover_find()`, and `sim.known_finds` gates effects such as willow, yarrow, salt and the bronze `finds` prerequisite; clan people are `E.Predator` with `kind` `"hunter"`/`"warrior"` and a `clan`, so combat code is shared). `improve` (`improve.gd`: the Steward lays out improvements from `config/rules.json` "improvements" (conditions via `story.holds()`); several wanted → `sim.advice_wanted` → HUD `llm.advise_build()` → `improve.choose()`; `improve.order(type)` for a game master; `summary()`), `policy` (`policy.gd`: the Council's standing policies from `config/policies.json`; choices are effect sources folded by `inv` like inventions (`inv._sources()`), drift culture daily and run `on_start` via `story.run()`; `set_choice()` is the one way to change them; `council()`/`council_ctx()` → HUD `llm.council()`), `crisis` (`crisis.gd`: emergency mode from `config/emergency.json`: an attack on ours (or **Take command** on a contract emergency) starts a crisis; `main.gd` multiplies time by `crisis.slow()`; orders are verbs on the people in it, given as interrupts (`job.crisis`, moves with `hold` stay put) so their work resumes at `end()`; signals `crisis_started/ended`; `_new_sim()` sets `crisis.on = false`), `director` (`director.gd`: paces hardships from `config/director.json`: a tension score with per-level cap; rolled hardships call `director.allow(kind)` (or `take()` when they don't report themselves through `sim.happened`) before starting and retry later when refused; distress lowers the cap and runs mercy gifts; `_new_sim()` sets `director.on = false`), `life` (`life.gd`: everyday life from `config/life.json`; each person is one family line: meals in a ring at the fire (they interrupt work via `resume_job`), a moment on waking, idle acts picked by weight (job `type "life"`, `pose` drives the drawn pose), bonds between families (`u.bonds`, kin via `parent_id`), per-person `morale`/`fatigue` folded into `work_mul`/`unit_speed`, grief, speech marks (`u.say`, signal `sim.spoke`), and the `discontent` dilemma where a family may leave (`u.gone`: dead + buried but not a death); `_new_sim()` sets `life.on = false`), `react` (`reactions.gd`: how people respond to what happens around them; the rules call `sim.react.trigger(event, ctx)` and `config/reactions.json` lists the responses per event: verbs `cover`/`aid`/`flee`/`firefight`/`defend` with their numbers and texts; a response `interrupt()`s the current job into `u.resume_job` with `job.react = true` and `_end_errand()` restores it). Rules query these (e.g. `hz.cold_rate()`, `evo.has_trad()`), so new hardships/bonuses usually mean a query function plus a hook in `sim.gd`.
- `audio.gd` — music, ambience and sound effects, presentation only: listens to sim signals (`log_added`, `alert_raised`, `happened`, `sound_cue`...) and reads state; every sound is a recipe in `config/audio.json` rendered by `synth.gd` (no sound files; cached in `user://sound_cache/`). Buses Music/SFX/Ambience; volumes in `settings.cfg [audio]`.
- `save_game.gd` — save/load: a save holds the New Game settings (the map is rebuilt from them: scenarios and seeded random maps are deterministic; `main.gd` keeps them in `settings`) and every script variable of `sim`, its sub-systems and the `E.*` entities by reflection, as an object graph (shared references survive). **UPPERCASE vars are not saved** (they're config-derived and reloaded fresh), nor vars named `_cache…` (lookup tables that rebuild themselves, e.g. `sim._cache_nodes` behind `node_by_id()`), so name config-derived vars in UPPERCASE, caches `_cache…`, and everything else lowercase; new state is saved automatically. Loading = `main.load_from(slot)` → static `pending_load` → `reload_current_scene()` → `new_game()` then `decode_into()`; `hud.after_load()` reopens a pending dilemma or emergency. Autosave/slots in `config/save.json`.
- `world_view.gd` — isometric renderer + Tier-1 RTS input. `hud.gd` — all UI (built in code, custom Theme, modals pause the sim). `llm_client.gd` — async OpenAI-compatible client. `persona_engine.gd` — static, offline stand-in that returns the same JSON shape as the LLM.

**Task Contract flow (core PRD idea):** `contracts.negotiation_ctx()` → `llm.negotiate()` (or `Persona.propose()` offline / on any failure) → `contracts.sanitize()` (LLM output is untrusted: clamp numbers, whitelist actions/structures/techs, map aliases) → `contracts.create()` → executor in `contract_system.update()` with **zero LLM calls** until an abort condition (`enemy_attack`, `hp_below_N%`, `natural_disaster` — floods and blizzards via `sim.flags["flood_active"/"disaster_t"]`) sets `sim.paused` and emits `contract_interrupted`; HUD then calls `llm.emergency()` and `contracts.resolve(c, effect)`. Contracts have `kind` `"settle"` (east-bank outpost), `"research"` (experiments → `evo.breakthrough`) or `"war"` (fixed skeleton war_dance/scout → assault → loot|burn|break → return; defenders are `guard` clan warriors spawned by `rivals.defend()`; abort `heavy_losses`). Persona prompts include memory, culture/era (`evo.world_ctx()`, with a list of words for techs not yet discovered) and season (`hz.summary()`).

**Rule configs (`config.gd`, `docs/CONFIG.md`):** the rival clans' behaviour is in `config/rivals.json` (`rivals.C`; deeds via `rivals._deed()`), everyday rules and folk life in `config/rules.json` (`sim.RULES`, `folk.F`), the victory paths in `config/legacy.json` (`legacy.C`), and the numbers and texts of the forces of nature and hardships are in `config/events.json` (`hz.C`, `nat.C`; the eclipse is a dilemma in the shared format) and the reactions in `config/reactions.json`; the chieftain's dilemmas (flood, overpop, chosen, eras, festivals, rival clans) are in `config/dilemmas.json` (`sim.DILEMMAS`); every data dilemma (those, culture packs, the eclipse, `story.pose()` from outside) runs through `story.dilemma_view()/dilemma_choose()` with named vars from the caller, and new effects are `story.run()` actions (`story.ACTIONS`); `Config.load_cfg(name)` merges `user://config/<name>.json` over them and returns a shared, **read-only** dictionary (changing it is a script error; a test that needs other rules gives its sim a `duplicate(true)` copy). The parts of the day (dusk, night, dark, dawn, morning) are rules.json `day`: ask `sim.is_day_part(name)`, never compare `day_frac()` with a number. Don't hardcode new tuning or texts for these in the scripts: add keys to the json (texts need zh; `test_translations` checks `Config.texts()`).

**Cultures (`cultures.gd`, `culture.gd`):** a culture pack is data only (`cultures/<id>/culture.json` + `zh.json`, also `user://cultures/`). `Cultures.apply(id)` (called in `main.gd` *before* the map is made) resets and merges it into the **static vars** `D.INVENTIONS`, `D.FINDS`, `D.TRIBE_NAMES`, `D.BIRTH_NAMES`, `D.TEMPERAMENTS`, `D.CHOSEN` (bases are the `D.BASE_*` consts) and sets `D.CULTURE`; `Cultures.reset()` = base game, which is what tests get unless they apply one. `sim.cult` runs the pack's events (chronicle lines or `culture:<id>` dilemmas through `_check_events`), folk tales (one a night) and people (founders/wanderers/chosen/ancestors), and records game happenings (`cult.on_event`, called from `_fire_event` and nature/weather hooks) for `after` conditions. Conditions and actions are `story.gd`'s `holds()`/`run()`, shared with scenario scripts. Effects are data: `{"stat", "mul"|"add", "of"}` on inventions, culture finds and boons, folded by `inv.mul(stat, of)`/`inv.add(stat)`; the allowed stats are `D.EFFECT_STATS`. A new stat needs a hook in the rules. `Cultures.validate()` is strict, so packs with errors are skipped. Pack texts are translated by their `zh.json` (`I.add_strings`); `test_translations` checks them via `Cultures.missing_zh()`.

**Maps & game modes:** the map is a set of **static vars** in `data.gd` (`W/H`, `RIVERS`, `FORDS`, `VILLAGE`, `HOME`, `SITES`, `RIVALS`, `LANDMARKS`, `VOLCANO`, `TRIBE`, `SCRIPT`, `MAP`...) filled by `D.load_map(spec)` from either a scenario (`scenarios/*.gd`, registered in `scripts/scenarios.gd`; `Scenarios.apply(id)`; the default `the_ford` is the original hand-made map that tests rely on) or `mapgen.gd` (random map: rivers, fords, village, clans from `D.CLANS`, landmarks from `D.LANDMARK_KINDS`, sites, a random tribe from `D.TEMPERAMENTS`; no script). `sim.new_game()` applies the default scenario if no map is loaded; tests that generate a map must call `Scenarios.apply()` afterwards. Scenario triggers run in `story.gd` (`sim.story`; dilemmas go through `story.pending` → `_check_events`). Nothing may assume one river, a fixed ford or an "east bank": rivers are polylines, fords are points on them, and land is split into **regions** (`D.region_at`, `home_side`, `same_side`); use `D.river_dist/river_info/shore/is_water/ford_at`, `D.route()` (waypoints over fords; `sim.set_dest` uses it), `D.random_land`, `contracts.next_site()` for frontier settlements, and derive positions from `D.VILLAGE`/`D.FORDS`, never absolute coordinates. Wilderness counts scale with `D.area_k()`; herds split by region size (`sim.herd_sizes`). The kind of land is `D.LAND` (`lands.gd`, `config/lands.json`: steppe, parkland, woodland, old forest): forests, bushes, herds, weather chances, wildfire and grass colour read it, so use it rather than fixed numbers when the wild depends on how wooded or wet the land is; random maps pick it from the seed (`MapGen.generate(..., land)`), The Ford is parkland. A deep forest has thousands of nodes: avoid per-tick or per-frame loops over `sim.nodes` (use `node_by_id()`, `nodes_of(res)`, cheap checks first; people by id: `unit_by_id()` (also indexed); the tables rebuild themselves when a list grows, shrinks or is replaced, so don't swap elements of `units`/`nodes` in place; `world_view` syncs static nodes every `NODE_FULL_EVERY` frames). Player-visible map data (landmark names/texts, tribe names, scenario texts) are translation keys checked by `test_translations`.

**Coordinates & rendering:** sim works in flat world units. Screen = `iso(p) = ((x−y)·0.75, (x+y)·0.375)`; `uniso()` inverts it for picking. World draw order is a child-node stack: `Ground` (terrain map texture + `shaders/terrain.gdshader`; terrain *type* is encoded in the map texture's alpha) → `GroundFX` (wear paths, seasons, water fx, footprints) → decor chunks → `objects` (`y_sort_enabled`; one cached `Item` canvas item per tree/building/post/unit, positioned at its iso base so y-sort == depth; static items redraw only when their signature changes in `_sync_items/_touch`) → `Overlay` (fog of war, weather, labels). Draw helpers all use the `ci` indirection (`ci.draw_*`) so the same code paints into whichever canvas item is drawing.

**Pre-rendered 3D sprites (`art_baker.gd`):** like AoE2, models are built in code from primitive meshes and rendered once into a transparent `SubViewport` by an orthographic camera matched to the iso projection (yaw 45°, pitch 30°, 1.0607 px/unit, baked at 2×), lit by a sun + SSAO with a `shadow_to_opacity` ground catcher, materials from `shaders/bake.gdshader` (triplanar noise detail + snow). Organic shapes use `tube()`/`loft()` (lofted rings, e.g. animal bodies from the `BEASTS` body plans and jointed legs via `chain()`), `lumpy()` (noise-displaced primitives: thatch, boulders, foliage `clump()`s); `tune()` sets shader extras — countershading `under_*` and `stripe_*` work in *mesh* space, so use them only on lofts placed at the parent origin. Results cache to `user://art_cache_v<ART_VERSION>` — **bump `ART_VERSION` after changing any model** or old sprites keep loading. Villagers/animals are baked in 8 directions × animation frames; villager clothing is a separate white "_cloth" layer tinted with `u.color` at draw time. `world_view._sprite(key, ...)` draws a baked sprite and returns false if absent, in which case the older procedural drawing runs — keep that fallback (headless runs bake nothing). Rendering method is Forward+ (needed for SSAO in the bake).

**Localization:** English text *is* the translation key. Wrap player-visible strings in `tr("...")` (or `I.t()` in static funcs, `I = preload("res://scripts/i18n.gd")`); Chinese lives in `scripts/lang_zh.gd` (`STRINGS` dict). `test_translations` fails if any `tr()` key lacks Chinese, and placeholders (`%s/%d`) must stay in the same order (GDScript `%` is positional). Internal ids stay English: `u.act` activity strings are display text only (translated via `I.act()`): never compare them in logic; read `u.doing` (what the hands are busy with right now: `chop`, `build`, `fight`, `ritual`, `dance`..., set where the work happens and cleared each `update_unit`), the job's `type`/`pose`, or `u.play` for a child's game; animations (`world_view.DOING_ANIM`) and job sounds (`audio.json` `jobs`) key on `doing` too; unit names are ids (display via `tr(u.name)`); `u.title` is `"Steward"`/`"War Chief"`. Empty translations count as missing — use `I.plural_s()` for plural suffixes. A Simplified-Chinese system font fallback is installed in `I.install_cjk_font()` (macOS "PingFang SC" resolves to the HK face, which lacks simplified glyphs).

## Gotchas

- GDScript: one-line `for x: if y: z` nesting is invalid; `:=` can't infer types from Variant/ternary-of-Variant expressions; don't name locals `tr`, `log`, or `len` (shadow built-ins); `var x: Material = ...` when a variable may hold either ShaderMaterial or StandardMaterial3D.
- Don't poll `Input.is_key_pressed()` for map controls: macOS input methods can swallow key-ups of letters typed into text boxes. `world_view` tracks pan keys only when their press reached the map (`pan_held`).
- Night rest (`sim._night_rest`): between `day_frac()` 0.74 and 0.96, units whose job was given before `night_start()` (`u.job_t`) go to bed, and so does day-only work whenever it was ordered (rules.json `beds.day_only`, by `sim.work_kind(u)`: `renovate` = renovating/upgrading), and so do contract crews and envoys (except war parties, `_at_war`). Non-war contracts skip `update()` while `sim.camp_asleep()`. `main.gd` runs `NIGHT_FF`× speed while `sim.night_ff()` and their job is not run. Tests that tick past ~67 s of game time will see idle workers asleep. Resumed jobs restore `u.job_t = u.resume_t` so they don't count as night orders. Units asleep in huts (`sim.in_hut(u)`) are hidden, can't be picked, and are ignored by predators.
- To interrupt someone's work for an errand, call `sim.set_aside(u)` before giving the new job and `sim.end_errand(u)` when it is done; don't copy `u.job` into `u.resume_job` by hand (what was set aside first must win).
- Input from outside is type-checked at the boundary: `story.ACTION_TYPES`/`COND_TYPES` give each action and condition key its type (`story.type_ok()`); `run()` skips a malformed action, `holds()` is false for a malformed condition, dilemma options in the wrong shape aren't offered, `react.trigger()` cleans its ctx. A new action or condition key needs its type there. `test_boundaries` throws junk at every entry point and fails on any engine error (an `OS.add_logger` counter); `test_spend` checks that every action/condition in the configs, culture packs and scenario is well-formed.
- Pay prices with `sim.spend(cost)` (all or nothing, returns false if it can't be paid) and check with `sim.can_afford(cost)`; add with `sim.give(amounts)` (ignores ids not in `D.RESOURCES` and non-numbers, never goes below 0). Don't touch `sim.stock` by hand for a price or a gift from data or a game master; the resource ids are `D.RESOURCES` (one list, also used by culture-pack validation). Don't call another module's `_private` functions: make the function public (and give it a doc comment) when another module or a game master needs it.
- A building's radius is `sim.struct_r(s)` (walls have a chosen `s.size`), not `D.STRUCTURES[type]["r"]`; placement cost is `sim.place_cost(type, size)`. Building operations for the panel and a game master: `sim.renovate_one(id)`, `sim.upgrade(id, to)`, `sim.demolish(id)` (paths and refunds in `rules.json` "buildings").
- Dead units stay in `sim.units` (`dead`, then `buried`); `_burials()` fetches bodies to the auto-founded `burial_ground` structure (`s.graves`).
- The sim and its sub-systems point at each other (`x.sim`), so `main._exit_tree()` calls `sim.dispose()` on Restart/Load/quit to free the old game; anything new that holds the sim and is held by it is covered if its back-reference is named `sim`. `test_dispose` checks nothing is left.
- `sim.check_invariants()` lists what is broken in a running game (negative stock, an office and a title that disagree, a job type not in `sim.JOB_TYPES`, crews on missing contracts...); `test_smoke` plays days with every system on (as in the game, unlike `_new_sim()`) and checks it. Add a new job type to `JOB_TYPES`, and a rule that must always hold to `check_invariants()`.
- `tests/_new_sim()` sets `hz.level = "off"` so older tests stay deterministic; hardship tests switch it on explicitly.
- LLM: Z.ai GLM Coding Plan keys only work on the `zai_coding` preset (`api.z.ai/api/coding/paas/v4`); requests to Zhipu/Z.ai send `thinking: disabled` for ~2 s responses. Keys are stored only in `user://llm_settings.cfg`, never in the repo.
